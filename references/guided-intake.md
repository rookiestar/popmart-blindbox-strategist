# 引导式采集

当用户没有整理输入时，用对话完成建模。固定流程：

`无端偏好简报（进机器前，可选） → 截图解析 → 阻塞信息澄清 → 目标 → 逐款评分 → 必须抽 / 可换端或停止 → 卡片与预算 → 当前端校准 → 边界确认 → 决策合同 → 精确计算 → 新线索后全局重算`

## 触发与退出

- 用户把截图单独输入，或说“不知道怎么选”“你一步步问我”，立即进入引导模式。
- 用户已一次给齐必要信息时，吸收现有信息并从尚未完成的阶段继续；不要强迫其重走问答。
- 用户要求退出引导时，保留已确认信息，改为普通模式。
- 用户尚未进入抽盒机就给出偏好时，先做无端偏好简报（见下节），等待截图
  后继续，而不是要求其想象盒位。
- 引导模式不改变概率模型、策略定义或停止规则，只负责获得可靠输入。

## 职责边界

AI 负责识别截图中的系列、盒位、“不是”、已售或不可用位置、已使用的卡片和倒计时；用户只回答主观决策，以及截图无法可靠判断的事实。

具体规则：

1. 先读图，再问问题。不要让用户手抄已经清楚可见的内容。
2. 单元格、系列或倒计时看不清时，只问会阻塞下一步的那一项。
3. 缺少完整常规款列表时，优先读取截图、用户提供的商品页或官方公开资料；这属于建立盒型事实，不等于完整二手研究。
4. 已售但未知盒继续作为潜变量；不要要求用户猜内容。
5. 用户一条消息一次回答多个信息时全部吸收，不要重复询问已经解决的问题。

## 无端偏好简报

用户还没走到抽盒机、没有截图和盒位，但已经给出目标与评分时，先运行零端
简报，不要求其想象端位：

```bash
python3 scripts/blindbox_solver.py examples/synthetic-preference-briefing.json \
  --brief-preferences --format markdown
```

- 输入只需要 `regular_count`、完整评分和已确认的
  抽盒预算；不得编造盒位、排除或已售信息。
- 原样转交简报。数值是整端常规款无重复先验下的盲抽基线，不是任何
  已观察端的真实水平；报告自带 `current_tray_not_observed` 警告。
- 只有 `随便中个喜欢` 且存在喜欢款时给出无端参考线：以 5 个百分点为档
  严格改善盲抽基线，弱基线采用喜欢 40% / 总雷 35% / 硬雷 20% 锚点。
  用户确认后写入既有 `stop_rules`，不新增
  第二套入场线；其他策略到端后再校准。
- 用户到达机器并给出截图后进入 `parse`，沿用简报确认的评分、参考线和
  预算；不得因增加真实端而重置它们。

## 对话控制

正常模式每轮只问一个当前最关键的问题。问题可以提供选项，但必须允许用户用自然语言回答。

问题调度优先级：

1. 修复会导致模型无效的事实缺口，例如一个盒位的“不是”无法辨认。
2. 确定本轮选择目标。
3. 优先收集完整逐款评分；用户不愿打分时才退回该目标的最小分档或排序。
4. 确定用户是否必须抽，以及是否允许换端或停止。
5. 仅在可能改变动作时询问剩余卡片、是否愿意用卡和额外付费预算。
6. 运行评分校准后，让用户从当前真实可达取舍中确认边界。
7. 汇总决策合同并取得确认。

若用户跳过问题或说“不确定”，解释该信息会改变什么；能安全继续时给出可修改的建议值，并记录为建议而非已确认事实。不得把建议静默写入硬限制。

## 状态机

| `phase` | 已完成条件 | 下一动作 |
|---|---|---|
| `brief` | 用户到机器前给出偏好，零端简报已转交，参考线已确认或明确推迟到端后 | 等待截图；得到截图后进入 `parse` 并沿用简报结果 |
| `parse` | 截图中的系列、盒位、排除、状态、卡片和倒计时已尽量提取 | 检查阻塞事实 |
| `clarify` | 影响模型有效性的事实已确认 | 询问选择目标 |
| `goal` | 六种策略之一已确定，或已有足够信息推荐一个 | 优先收集逐款评分 |
| `preferences` | 全款评分完整，或用户明确选择旧式最小偏好 | 询问必须抽、换端与停止权限 |
| `commitment` | 行动边界清楚 | 只在相关时询问卡片和预算 |
| `tools` | 当前可用道具与付费意愿清楚，或已确认无需道具规划 | 当前端评分校准 |
| `calibration` | 已展示真实可达区间，且用户确认具体候选边界或修改数字 | 输出决策合同 |
| `contract` | 用户明确确认合同 | 写入最终状态并精确计算 |
| `ready` | 已输出建议 | 等待真实新线索并全局重算 |

`phase` 只记录下一项未完成工作。用户提前提供后续信息时，可跨过已完成阶段。

## 第一个主观问题

没有阻塞事实后，使用：

```text
第1步：这次你最看重什么？
A. 尽量别踩雷
B. 任意喜欢款都可以
C. 只冲最想要的那款
D. 综合下来最满意
E. 优先保值

没有明确目标时默认建议 A。回复字母或自然语言即可。
```

映射规则：

- A 先映射为 `稳妥避雷`；若用户有明确硬雷且愿意设置风险上限，再切换为 `守住底线`。
- B 映射为 `随便中个喜欢`。
- C 映射为 `只冲最爱`。
- D 映射为 `整体最满意`。
- E 映射为 `保值优先`。

不要把默认建议 A 写成用户已经选择。用户回答含糊时，只需确认其真正的主要取舍。

## 评分问题与旧式回退

A–E 五个主目标都优先只问一次完整评分：

```text
请给每个常规款打 -10 到 +10 分；我会自动分成最爱、喜欢、可接受、中性、
中性但失望、轻雷、硬雷。你不需要先估概率上限。

如果确有一组款完全同感，可以说“其余款都 0 分”；我会复述确认后才统一补齐。
```

评分必须覆盖所有常规款。仅当用户明确确认“其余款同分”时，才设置
`score_default` 与 `score_default_confirmed: true`。用户不愿逐款评分时，
保留下列旧式最小输入，不强迫其打分：

| 策略 | 最少必须知道 | 推荐问法 |
|---|---|---|
| `稳妥避雷` | 按严重程度排列的不喜欢款；也可明确“没有不喜欢” | “哪些款抽到会最失望？从最不能接受的开始说即可。” |
| `守住底线` | 满意度评分或足以生成评分的分档、硬雷身份；上限在校准后确认 | “先告诉我硬雷、轻雷、喜欢和最爱；没提到的可统一视为中性吗？” |
| `整体最满意` | 各款评分，或少量显式评分加一个其余款默认分 | “给最爱、喜欢、失望和雷款打 `-10` 到 `+10`；其余款可统一给一个分数。” |
| `随便中个喜欢` | 喜欢款集合；若有先后可附排序 | “哪些款抽到都算满意？” |
| `只冲最爱` | 最爱集合；若显式逐款排序则保留顺序 | “哪些款都是不可替代的最爱？若有先后再告诉我。” |
| `保值优先` | 当前、同口径的常规款市场价值 | 触发市场研究；数据不可用时说明不能可靠使用该策略，并请用户改选目标或提供资料。 |

完整二手研究只在以下情况触发：

- 用户选择 `保值优先`；
- 用户主动询问市场、热度或价格；
- 识别系列、常规款列表或盒型确有需要，且无法从截图或官方资料建立必要事实。

第三种情况只收集建模所需事实，不顺带生成二手排行。

## 行动与道具边界

偏好完成后，依次确定：

1. 这次是否必须抽一盒。
2. 当前端不合格时，是否允许换端。
3. 整轮是否允许停止，以及最多抽几盒。
4. 现有提示卡、显示卡数量。
5. 是否愿意额外付费购买道具，以及明确预算。

只问会改变动作的项目。例如没有卡且不考虑购买时，不讨论复杂道具规划；用户明确必须抽时仍要展示风险，但在可用盒中选最符合目标者，不得把“最佳”写成“安全”。

## 当前端评分校准

完整评分、行动边界和必要道具信息齐备后，先运行。`保值优先`必须先完成
市场研究，并为全部常规款写入当前、同口径的 CNY `market_values`：

```bash
python3 scripts/blindbox_solver.py <state.json> \
  --calibrate-preferences --format markdown
```

原样转交校准报告。该报告只做四件事：

1. 自动复述七档及评分覆盖；
2. 展示当前端全部可选盒的最爱、喜欢、不喜欢、硬雷和期望评分；选择
   `保值优先`时同时展示预期二手价值；
3. 给出真实可达区间及未被其他盒全面压过的选项；
4. 生成最多三个具体候选：目标优先、硬雷最低、总雷最低。

`只冲最爱` 以所有 `+10` 款合计概率为主目标；不喜欢和硬雷仅作为待校准
风险。候选边界向参考盒仍可通过的方向取整，但不自动写入状态。不得从分数
机械推出概率线，也不得套用固定 `15%`。

`保值优先`以预期二手价值为主目标，同时把期望个人评分、不喜欢和硬雷作为
待确认边界。市场值缺失、口径不一或已过期时不得进入校准。

提示用户：回复方案1/2/3即确认该组边界用于本系列当前会话，也可修改数字。
确认前保留 `stop_rules` 中已确认的抽盒预算，不增加质量线，不输出正式抽盒
建议。用户确认后才写入对应 `min_*` / `max_*`；若切换为 `守住底线`，再将
确认的硬雷边界写入 `hard_avoid_max_pp`。

若目标在当前端所有可选盒均为 `0`，不生成数值为 `0` 的伪门槛；建议换端或停止。
换系列或评分实质变化时重新校准。同系列仅新增提示或换端时沿用已确认边界并
全局重算。

## 决策合同与完成门槛

精确计算前，必须用一段紧凑摘要列出：

- 识别到的系列、端和关键不确定性；
- 策略及一句话规则；
- 最爱、喜欢、可接受、中性但失望、轻雷、硬雷中实际需要的项目；
- 必须抽、可换端、可停止和最多抽数；
- 可用卡片及额外付费边界；
- 用户明确同意的概率/评分/保值停止线；
- 校准选项及其参考盒；
- 所有建议默认值。

用户必须明确确认，或直接修改其中一项。只有明确确认后，才将 `meta.guidance.confirmed` 设为 `true`、进入最终精确计算并输出抽盒建议。沉默、模糊回应和 AI 建议都不算确认。

## 三分钟快车道

识别到剩余倒计时不足约 3 分钟，或用户明确说时间紧时，进入快车道：

1. 仍先读取截图并只澄清模型阻塞项。
2. 不再每轮只问一个，而是一次收集最少必要信息：

```text
时间紧，请一条回复：
1）目标 A避雷 / B任意喜欢 / C只冲最爱 / D整体满意 / E保值；
2）若已打分，直接粘贴全部评分；否则说最爱、喜欢、硬雷；
3）必须抽，还是可换端/停止；
4）提示卡和显示卡各几张。
```

3. 已从用户前文或截图得到的项目从问题中删除。
4. 跳过完整市场研究；仅 `保值优先` 无法缺少市场值，数据不足时立即建议改选非市场策略。
5. 完整评分已存在时运行校准快报并让用户选边界；否则使用旧式最小偏好，
   不替用户补造评分或概率线。
6. 回复决策合同，请用户确认；确认后运行一步规划，不在倒计时内默认运行深度二。

快车道减少轮次，不降低事实准确性，也不替用户接受风险。

## 新线索

进入 `ready` 后，用户报告提示、显示或开盒结果时：

1. 判断是真实事件还是“如果”分支。
2. 吸收一条消息中的全部新信息。
3. 更新真实状态或独立反事实分支。
4. 对整端全局重算。
5. 仅当目标、行动边界或风险偏好确实变化时，重新进入相应引导阶段。
